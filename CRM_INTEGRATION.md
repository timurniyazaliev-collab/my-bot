# Подключение CRM «Sales» — что отдать разработчикам

Два способа подключить ИИ-менеджера к CRM. Решает не CRM-разработчик
сам по себе, а то, что реально умеет их система — стоит уточнить у них
на встрече, какой вариант им удобнее.

## Вариант А. Готовый вебхук (рекомендую)

У бота уже есть весь "мозг" продаж — факты о проекте, ответы на
возражения, когда передать лида менеджеру, какие фото прислать. Вебхук
(`webhook_server.py`) открывает этот мозг наружу одним адресом: CRM
присылает туда сообщение клиента, в ответ получает готовый текст +
флаг "пора звать менеджера" + ссылки на нужные фото. CRM-разработчикам
почти ничего не нужно писать самим — вся логика продаж уже готова и
проверена в Telegram.

Что отдать разработчикам:
- Адрес: `https://<ваш-домен-или-IP>/api/lead-reply`
- Ключ доступа (`X-API-Key`) — отдельный секретный ключ для CRM, не
  Anthropic-ключ. Смотри "Как запустить" ниже.

Формат запроса (CRM → нам), POST `/api/lead-reply`:
```json
{
  "lead_id": "уникальный id диалога/клиента в CRM",
  "message": "текст, который написал клиент"
}
```

Формат ответа (мы → CRM):
```json
{
  "reply": "текст, который нужно показать клиенту",
  "escalate": false,
  "escalation_card": null,
  "photos": [
    {"category": "exterior_yard", "urls": ["https://.../media/exterior/yard_01.jpg"]}
  ]
}
```
- `escalate: true` — значит пора подключить живого менеджера,
  `escalation_card` — карточка лида с деталями для него.
- `photos` — какие фото/планировки прислать клиенту и прямые ссылки
  на файлы (CRM просто скачивает их по ссылке и отправляет клиенту).

Диалог CRM ведёт по `lead_id` — сервер сам помнит историю переписки,
CRM не обязана присылать её целиком каждый раз.

### Как запустить (сделать один раз на сервере)

1. Сгенерировать секретный ключ для CRM (не Anthropic-ключ, а свой):
   `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`
2. Добавить в `.env` на сервере (`/root/my-bot/.env`):
   `WEBHOOK_API_KEY=<сгенерированный ключ>`
3. Запустить `webhook_server.py` как отдельный сервис (по образцу
   `mybot.service`), например `mybot-webhook.service`, слушает порт
   8000 по умолчанию (`WEBHOOK_PORT` можно поменять).
4. Нужен публичный адрес с HTTPS, по которому CRM сможет достучаться
   до порта 8000 — это через домен + обратный прокси (nginx/Caddy) с
   SSL-сертификатом. Если домена ещё нет — для первого теста можно
   временно дать CRM-разработчикам IP сервера и порт напрямую
   (`http://<IP>:8000`, без HTTPS), но для реальной работы с клиентами
   нужен нормальный домен с HTTPS — это стоит сделать до релиза.

Этот шаг (домен, nginx, systemd-сервис) проще всего сделать вместе с
разработчиками CRM на завтрашней встрече — они наверняка уже
разворачивали похожие интеграции.

## Вариант Б. Просто дать доступ к Claude напрямую

Если у CRM «Sales» есть встроенная функция "подключить свою нейросеть"
(просто поле для API-ключа и системного промпта, без вебхука) — тогда
это быстрее всего.

1. Получить отдельный ключ Anthropic (не тот, что уже стоит у бота —
   чтобы CRM не могла случайно сломать или объесть лимит Telegram-бота,
   и чтобы ключ можно было отозвать отдельно):
   - Зайти на https://console.anthropic.com
   - Settings → API Keys → Create Key
   - Назвать понятно, например `crm-sales-2026`
   - Скопировать ключ (он покажется один раз) и отправить разработчикам
2. Сказать им модель: `claude-opus-5`
3. Дать текст системного промпта — это содержимое `lead_manager.md` +
   `zhk_dubai.md` (можно просто переслать оба файла).

Важно: в этом варианте вся логика — когда передавать лида менеджеру,
когда и какие фото присылать, память переписки — CRM-разработчикам
придётся писать заново внутри CRM, потому что просто ключ и промпт
этого не умеют сами по себе. Наш промпт сейчас рассчитан на вариант А
(в нём есть технические метки для эскалации и фото) — если выбираете
вариант Б, эти метки в промпте разработчикам либо нужно убрать, либо
научить CRM их понимать. Дай знать, какой вариант выбрали — при
необходимости адаптирую промпт под вариант Б отдельно.
