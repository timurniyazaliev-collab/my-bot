
# Telegram-бот на Claude



Главный файл — bot.py (всё, что специфично для Telegram: команды,

клавиатура, напоминания). Сам "мозг" — знания о проекте, скрипты,

системные промпты, вызов Claude — вынесен в sales_ai.py, он не знает

про Telegram и рассчитан на переиспользование другими каналами

(WhatsApp, Instagram, сайт), когда они появятся. Зависимости —

requirements.txt.



## Сервер

Бот работает на VPS DigitalOcean.

- Путь: /root/my-bot

- Сервис: mybot.service (systemd)

- Автодеплой: /root/autodeploy.sh запускается ежеминутно,

  делает git pull и перезапускает сервис при изменениях.



## Workflow

Всё через GitHub: коммит в main → через минуту сервер обновится.

Руками на сервер не лезем.



## Бизнес-контекст и маркетинг-команды

- `business.md` — описание бизнеса (S House Group, ЖК Dubai), ключевые
  слова и конкуренты. Подставляется в системные промпты команд ниже.
  Пользователь может редактировать этот файл сам через GitHub.
- `/news`, `/competitors`, `/mentions` — используют веб-поиск Claude
  (`web_search_20260209`, модель `claude-opus-5`), чтобы отвечать на
  основе реальных актуальных данных, а не выдумывать факты.
- `/idea`, `/post`, `/reels` — генерация контента для Instagram, без
  веб-поиска, на основе `business.md`.

## ИИ-менеджер для клиентов (лидов)

Бот умеет отвечать не только Тимуру, но и реальным клиентам ЖК Dubai,
которые напишут ему в Telegram.

- Первый, кто нажмёт `/start` после деплоя (то есть Тимур), становится
  «владельцем» — его chat_id сохраняется в `owner_chat_id.txt`. Только
  владелец видит внутренние команды (`/news`, `/sales`, `/wb_*` и т.д.)
  и общается с ботом как с личным помощником.
- Любой другой человек, который напишет боту, автоматически попадает в
  режим ИИ-менеджера по продажам: бот квалифицирует лида, отвечает на
  вопросы и возражения по проекту, предлагает показ — по инструкции из
  `lead_manager.md`. Этот файл можно редактировать прямо на GitHub
  (факты о проекте, стиль общения, возражения, правила передачи лида).
- Когда бот решает, что лида пора передать живому менеджеру (клиент
  готов к брони, спрашивает то, что вне базы знаний, или пишет
  негативно) — он сам присылает владельцу (Тимуру) карточку лида со
  ссылкой на диалог с этим человеком в Telegram.
- Если лид долго молчит — бот сам напомнит о себе через 24 часа, а
  через 3 дня без ответа пришлёт Тимуру уведомление, что лида пора
  написать напрямую.
- Бот умеет присылать лиду настоящие фото комплекса: они лежат в
  `media/<категория>/` (сейчас только `media/exterior/`), взяты из
  папки "ЖК Dubai" на Google Диске. Когда фото нужны по ходу
  разговора, модель сама решает это и добавляет техническую метку —
  логика в `sales_ai.py`/`bot.py`, для бизнес-контента (когда уместно
  показывать фото) правки в `lead_manager.md`. Чтобы добавить новую
  категорию (например, планировки, когда их загрузят) — положить
  файлы в новую подпапку `media/...` и прописать её в `bot.py`
  (`PHOTO_CATEGORIES`) и `sales_ai.py` (`PHOTO_CATEGORIES_AVAILABLE`).

## Другие каналы (WhatsApp, Instagram, Facebook, сайт)

Планируется подключить тот же ИИ-менеджер (`sales_ai.py`) к другим

каналам, кроме Telegram. WhatsApp, Instagram Direct и Facebook

Messenger подключаются через один аккаунт Meta Business Manager —

шаги для этого расписаны в `META_CHANNELS_SETUP.md`, их нужно делать

вручную (верификация бизнеса), это не через GitHub. Сайт-виджет проще

всего — обычный веб-чат, который стучится в sales_ai.py, без

одобрения третьей стороны. Пока WhatsApp/Instagram/Facebook не

подключены — код готов (мозг отделён от Telegram-кода), но

обработчиков вебхуков для них ещё нет.



Для CRM «Sales» вебхук уже готов — `webhook_server.py` (Flask,

отдельный процесс от Telegram-бота), открывает `sales_ai.py` наружу

одним HTTP-адресом. Детали интеграции и запуска — в

`CRM_INTEGRATION.md`.
